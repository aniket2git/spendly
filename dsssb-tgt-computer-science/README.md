## How to use it

1. Read a chapter slowly once. Don't memorise — understand the everyday example first.
2. Re-read only the **bold** lines and the **NOTE** / **TIP** boxes.
3. Attempt the Part L papers closed-book. Score yourself **+1** correct, **−0.25** wrong, **0** skipped.
4. Write down the *topic* of every question you get wrong. That list is your real syllabus.
5. In the final 7 days, revise **only Part M**.

## Highest-value sections

- **Part M** — everything memorisable in one place. Best marks per hour of study.
- **Part K** — Teaching Methodology. The easiest ~20 marks in the paper; most candidates lose them carelessly.
- **Part C** — Operating Systems. The single biggest Computer Science scorer (8–12 questions per paper).
- **Part L** — the solved papers. Re-solve until every explanation feels obvious.

## A note on the answer keys

Nine questions in the original papers have official answer keys that conflict with
standard textbook theory. For example:

| Question | Official key | Standard theory |
|---|---|---|
| Standard defining web server ↔ application program communication | HTTP | **CGI** |
| Layer that sends data as a raw bit stream | Data Link | **Physical** |
| Header for C variable-argument lists | `stdio.h` | **`stdarg.h`** |
| `SUM 1/(n²)^(1/5)` convergence | convergent | **divergent** (p = 0.4 ≤ 1) |
| `printf(6+"Hello World\n")` | compilation error | prints **`World`** |

Each is flagged **KEY NOTE** inside the book with both answers and guidance on which
to choose, so you can handle either framing in the exam.
