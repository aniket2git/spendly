## 3.1 OS Concepts, Processes and Threads

### 3.1.2 Questions



**Q. [PYQ] Which of the following services is NOT provided by the operating system?**

- (a) Resource management
- (b) Inter process for communication
- (c) **Translate source into machine code  <-- CORRECT**
- (d) Program execution

> **Why:** Translation is the **compiler's** job. The OS *runs* the compiler but performs no translation itself. Genuine OS services: process management, memory management, file management, I/O, IPC, protection, error detection, accounting.



**Q. [EXPECTED] Which of the following is NOT a function of an operating system?**

- (a) Memory management
- (b) Process scheduling
- (c) File management
- (d) **Designing the database schema  <-- CORRECT**

> **Why:** Schema design is a human/DBA activity in DBMS. Keep the OS's remit clear: it manages the machine's **resources**.



**Q. [EXPECTED] The core part of the operating system that is always resident in memory is called:**

- (a) Shell
- (b) **Kernel  <-- CORRECT**
- (c) Compiler
- (d) BIOS

> **Why:** The **kernel** handles scheduling, memory, drivers, system calls and interrupts, and never leaves memory. The **shell** is the outer command interpreter.



**Q. [EXPECTED] [TRAP] Which kernel type runs file systems and device drivers in user space?**

- (a) Monolithic kernel
- (b) **Microkernel  <-- CORRECT**
- (c) Hybrid kernel
- (d) Exokernel

> **Why:** A **microkernel** keeps only scheduling, memory and IPC in kernel space; everything else runs as user processes. Result: very reliable and modular, but slower because of message-passing overhead. **Monolithic** (Linux, UNIX) puts everything in kernel space - fast but a single bug can crash the system.



**Q. [EXPECTED] A system call causes a transition from:**

- (a) kernel mode to user mode
- (b) **user mode to kernel mode  <-- CORRECT**
- (c) user mode to user mode
- (d) kernel mode to kernel mode

> **Why:** A system call is the controlled doorway into privileged execution. This **dual-mode** design is what stops a user program from touching hardware directly.



**Q. [EXPECTED] Which of the following is a process-control system call?**

- (a) open()
- (b) read()
- (c) **fork()  <-- CORRECT**
- (d) ioctl()

> **Why:** The five system-call categories: **process control** (fork, exec, exit, wait), **file management** (open, close, read, write), **device management** (ioctl), **information maintenance** (getpid, time), **communication** (pipe, socket, shmget).



**Q. [PYQ] What is typically returned by the getpid system call in Unix-based operating systems?**

- (a) The process ID of the kernel
- (b) **Process ID of the current process  <-- CORRECT**
- (c) Process ID of the first process
- (d) Process ID of the parent process

> **Why:** `getpid()` returns the caller's own PID; **`getppid()`** - note the extra p - returns the **parent's** PID. A guaranteed pair question.



**Q. [EXPECTED] [TRAP] What is the difference between a program and a process?**

- (a) They are identical
- (b) **A program is passive code on disk; a process is a program in execution  <-- CORRECT**
- (c) A process is stored on disk and a program in memory
- (d) A program can have only one process

> **Why:** A program is a **passive** file (a recipe); a process is an **active** entity with a program counter, registers, stack and memory (actually cooking). One program can spawn many processes.



**Q. [EXPECTED] Which of the following is NOT stored in the Process Control Block?**

- (a) Process state
- (b) Program counter
- (c) CPU register values
- (d) **The complete source code of the program  <-- CORRECT**

> **Why:** The PCB holds process **metadata**: PID, state, PC, registers, scheduling info, memory-management info, accounting data, I/O status. Source code is never in the PCB.



**Q. [PYQ] An operating system completely releases the memory allocated to a process after the process transitions from which of the following states?**

- (a) Sleeping to ready
- (b) Ready to running
- (c) **Running to terminated  <-- CORRECT**
- (d) Running to sleeping

> **Why:** Memory is reclaimed only when the process **ends**. A sleeping or ready process will resume later and must find its data intact.



**Q. [EXPECTED] [TRAP] Which process state transition is NOT possible?**

- (a) Running to Ready
- (b) Waiting to Ready
- (c) Running to Waiting
- (d) **Waiting to Running  <-- CORRECT**

> **Why:** A blocked process whose event completes always returns to the **Ready queue** and must be re-dispatched by the scheduler - it can never jump straight onto the CPU. Also impossible: Ready to Waiting, and anything out of Terminated.



**Q. [PYQ] If a process arrives at time 5, what is the latest possible time for it to start execution if there are no other processes in the system?**

- (a) Time 6
- (b) Time 0
- (c) **Time 5  <-- CORRECT**
- (d) Time 4

> **Why:** With no competition the scheduler dispatches it immediately on arrival, and it cannot begin before it exists. So earliest = latest = **5**.



**Q. [EXPECTED] A thread shares which of the following with other threads of the same process?**

- (a) Program counter
- (b) Stack
- (c) Register set
- (d) **Code, data and open files  <-- CORRECT**

> **Why:** Threads share the **address space** (code, data, heap) and open files. Each thread keeps its own **program counter, registers and stack**. Hence a thread is "lightweight".



**Q. [EXPECTED] [TRAP] What is the main disadvantage of user-level threads?**

- (a) They are slow to create
- (b) **If one thread blocks, the entire process blocks  <-- CORRECT**
- (c) They cannot share memory
- (d) They need more memory than kernel threads

> **Why:** The kernel is unaware of user-level threads, so a blocking system call in one blocks the whole process, and the threads cannot be spread across multiple cores. Kernel-level threads avoid both problems at the cost of slower management.



**Q. [PYQ] ______ and ______ are used in conjunction for making a complete process subroutine.**

- (a) **fork(), join()  <-- CORRECT**
- (b) fork(), sleep()
- (c) sleep(), join()
- (d) join(), fork()

> **Why:** `fork()` **splits** execution into parent and child; `join()`/`wait()` **merges** by waiting for completion. Order matters - you cannot join before you fork. Failing to wait leaves **zombie** processes.



**Q. [EXPECTED] What does fork() return in the child process?**

- (a) The child's PID
- (b) The parent's PID
- (c) **0  <-- CORRECT**
- (d) -1

> **Why:** `fork()` returns **0 to the child**, the **child's PID to the parent**, and **-1 on failure**. This asymmetry is how a single piece of code knows which process it is running in.



**Q. [EXPECTED] [NUMERICAL] How many total processes exist after three successive fork() calls?**

- (a) 3
- (b) 4
- (c) 6
- (d) **8  <-- CORRECT**

> **Why:** Each fork doubles the process count, so n forks give **2^n** processes: 2^3 = **8** total, meaning 7 new children.



**Q. [EXPECTED] A process that has terminated but whose parent has not yet collected its exit status is called:**

- (a) Orphan process
- (b) **Zombie process  <-- CORRECT**
- (c) Daemon process
- (d) Suspended process

> **Why:** A **zombie** is dead but still holds a PCB entry awaiting `wait()`. An **orphan** is a live process whose parent died; it is adopted by init/systemd (PID 1).



**Q. [PYQ] What is an endpoint of an inter-process communication?**

- (a) Tunnel
- (b) Port
- (c) **Socket  <-- CORRECT**
- (d) Pipe

> **Why:** A **socket** is one endpoint of a two-way communication link, identified by **IP address + port + protocol**. A *port* is merely one component of a socket address; a *pipe* is a channel, not an endpoint, and is not network-capable.



**Q. [EXPECTED] Which IPC mechanism is the fastest for transferring large amounts of data?**

- (a) Pipe
- (b) Message queue
- (c) **Shared memory  <-- CORRECT**
- (d) Signal

> **Why:** **Shared memory** maps one region into both processes, so after setup no kernel copying occurs. Pipes and message queues copy through the kernel; signals carry almost no data.



**Q. [EXPECTED] A binary semaphore whose value can only be 0 or 1 is functionally similar to a:**

- (a) Monitor
- (b) **Mutex lock  <-- CORRECT**
- (c) Counting semaphore
- (d) Condition variable

> **Why:** A **mutex** provides mutual exclusion for one resource. A **counting semaphore** permits up to N concurrent holders. Semaphore operations: `wait()`/P()/down() decrements, `signal()`/V()/up() increments.



**Q. [EXPECTED] Which of the following is NOT one of the four necessary conditions for deadlock?**

- (a) Mutual exclusion
- (b) Hold and wait
- (c) No preemption
- (d) **Starvation  <-- CORRECT**

> **Why:** The four are **mutual exclusion, hold and wait, no preemption, circular wait**. **Starvation** is a different problem - the system still progresses, just not for one unlucky process. Its cure is **aging**.



**Q. [EXPECTED] [TRAP] The Banker's algorithm is used for deadlock:**

- (a) prevention
- (b) **avoidance  <-- CORRECT**
- (c) detection
- (d) recovery

> **Why:** **Avoidance** - it permits the four conditions but tests every request to keep the system in a **safe state**. *Prevention* structurally forbids one condition; *detection* lets deadlock happen and finds it with a wait-for graph. Dijkstra devised the Banker's algorithm.



**Q. [EXPECTED] Real operating systems such as UNIX and Windows handle deadlock mainly by:**

- (a) the Banker's algorithm
- (b) resource ordering
- (c) **largely ignoring it and relying on restart  <-- CORRECT**
- (d) full detection and rollback

> **Why:** Deadlock is rare enough in practice that the overhead of avoidance is not worth it - this is sometimes called the "ostrich algorithm". Good to know because it counters the textbook assumption.



## 3.2 CPU Scheduling



> **WEIGHTAGE: 2-4 marks | Definitions and one numerical are typical | Priority CRITICAL**



### 3.2.1 Questions



**Q. [PYQ] [TRAP] Which of the following statements is FALSE?**

- (a) **Burst Time: Time required by a process to start its execution  <-- CORRECT**
- (b) Turn Around Time: difference between completion time and arrival time
- (c) Completion Time: time at which a process completes its execution
- (d) Arrival Time: time at which a process arrives in the ready queue

> **Why:** **Burst time is the time a process needs ON THE CPU to execute**, not the time to start. Examiners change "to execute" into "to start its execution" - a one-word swap that flips the statement.



**Q. [EXPECTED] Turn Around Time is calculated as:**

- (a) Burst Time - Arrival Time
- (b) **Completion Time - Arrival Time  <-- CORRECT**
- (c) Completion Time - Burst Time
- (d) Waiting Time + Arrival Time

> **Why:** **TAT = CT - AT**, and **WT = TAT - BT**. These two formulas solve every scheduling numerical. Build a table with columns AT, BT, CT, TAT, WT.



**Q. [EXPECTED] [NUMERICAL] Three processes arrive at time 0 with burst times 5, 3 and 8, scheduled by FCFS in that order. What is the average waiting time?**

- (a) 2.67
- (b) **4.33  <-- CORRECT**
- (c) 5.33
- (d) 6.00

> **Why:** Waiting times are 0, 5 and 8 (each waits for all previous bursts). Average = (0 + 5 + 8)/3 = 13/3 = **4.33**.



**Q. [EXPECTED] Which scheduling algorithm gives the minimum average waiting time among non-preemptive algorithms?**

- (a) FCFS
- (b) **SJF  <-- CORRECT**
- (c) Round Robin
- (d) Priority

> **Why:** **Shortest Job First** is provably optimal for average waiting time, but it needs burst times known in advance and can **starve** long jobs. Its preemptive form is **SRTF**.



**Q. [EXPECTED] The convoy effect is a problem associated with:**

- (a) SJF
- (b) Round Robin
- (c) **FCFS  <-- CORRECT**
- (d) Priority scheduling

> **Why:** In **FCFS**, one long CPU-bound process at the head makes all short processes wait behind it, like a convoy stuck behind a slow truck. This is why FCFS has poor average waiting time.



**Q. [EXPECTED] [TRAP] In Round Robin scheduling, what happens if the time quantum is made very large?**

- (a) It becomes SJF
- (b) **It behaves like FCFS  <-- CORRECT**
- (c) It causes starvation
- (d) Context switching increases

> **Why:** With a quantum longer than every burst, no preemption ever occurs, so RR degenerates to **FCFS**. A very *small* quantum has the opposite problem: excessive context-switch overhead.



**Q. [EXPECTED] Which scheduling algorithm is most suitable for a time-sharing system?**

- (a) FCFS
- (b) SJF
- (c) **Round Robin  <-- CORRECT**
- (d) Priority without aging

> **Why:** Round Robin guarantees each process the CPU within a bounded time, which is exactly what interactive response requires.



**Q. [EXPECTED] Starvation in priority scheduling is solved by:**

- (a) Preemption
- (b) **Aging  <-- CORRECT**
- (c) Increasing the time quantum
- (d) Using FCFS

> **Why:** **Aging** gradually raises the priority of long-waiting processes so they eventually run.



**Q. [EXPECTED] Which scheduler controls the degree of multiprogramming?**

- (a) Short-term scheduler
- (b) **Long-term scheduler  <-- CORRECT**
- (c) Medium-term scheduler
- (d) Dispatcher

> **Why:** The **long-term (job) scheduler** decides which jobs enter the ready queue, thereby fixing how many processes are in memory. The **short-term** scheduler picks who runs next (milliseconds); the **dispatcher** performs the actual context switch.



**Q. [EXPECTED] A context switch is best described as:**

- (a) useful computation
- (b) **pure overhead with no useful work done  <-- CORRECT**
- (c) a form of scheduling algorithm
- (d) an I/O operation

> **Why:** During a context switch the CPU only saves and restores state. Minimising switches is therefore a real performance goal.



## 3.3 Memory Management and Virtual Memory



> **WEIGHTAGE: 3-4 marks | Paging and page replacement recur constantly | Priority CRITICAL**



### 3.3.1 Questions



**Q. [PYQ] [TRAP] How does the Best Fit algorithm impact system performance?**

- (a) It improves system performance by reducing memory wastage.
- (b) **It may reduce system performance due to increased search time for free blocks.  <-- CORRECT**
- (c) It always improves system performance.
- (d) It improves system performance by reducing external fragmentation.

> **Why:** Best Fit must scan the **entire** free list on every request, and the tiny leftover holes it creates actually **worsen** external fragmentation. Note that three of the four options praise it - the word "always" alone disqualifies one of them.



**Q. [EXPECTED] Which allocation algorithm scans from the start and takes the first sufficiently large hole?**

- (a) Best Fit
- (b) **First Fit  <-- CORRECT**
- (c) Worst Fit
- (d) Next Fit

> **Why:** **First Fit** is the fastest to search and performs well in practice. **Worst Fit** takes the largest hole and performs poorly. **Next Fit** resumes scanning from the last position.



**Q. [EXPECTED] [TRAP] Wasted space inside an allocated block is called:**

- (a) External fragmentation
- (b) **Internal fragmentation  <-- CORRECT**
- (c) Compaction
- (d) Thrashing

> **Why:** **Internal** fragmentation is unused space *within* an allocated block (typical of fixed partitions and **paging**). **External** fragmentation is free memory scattered in pieces too small to use (typical of variable partitions and **segmentation**), cured by **compaction**.



**Q. [EXPECTED] Paging eliminates which problem?**

- (a) Internal fragmentation
- (b) **External fragmentation  <-- CORRECT**
- (c) Thrashing
- (d) Page faults

> **Why:** Because any page can occupy any free frame, contiguity is no longer required, so external fragmentation disappears. A little internal fragmentation remains in each process's last page.



**Q. [EXPECTED] [TRAP] Which statement correctly distinguishes paging from segmentation?**

- (a) Paging uses variable-size blocks; segmentation uses fixed-size
- (b) **Paging uses fixed-size blocks decided by the OS; segmentation uses variable-size logical divisions visible to the programmer  <-- CORRECT**
- (c) Both use fixed-size blocks
- (d) Segmentation causes internal fragmentation

> **Why:** **Paging**: fixed size, OS-decided, invisible to the programmer, internal fragmentation. **Segmentation**: variable size, logical (code/data/stack segments), visible to the programmer, external fragmentation.



**Q. [EXPECTED] The hardware cache that speeds up page-table lookups is called:**

- (a) Page table base register
- (b) **TLB  <-- CORRECT**
- (c) Frame buffer
- (d) Cache line

> **Why:** The **Translation Lookaside Buffer** stores recent page-to-frame mappings. Without it every memory reference would need two memory accesses - one for the page table, one for the data.



**Q. [PYQ] What is the main purpose of virtual memory?**

- (a) **To extend the physical memory using secondary storage  <-- CORRECT**
- (b) To provide cache storage
- (c) To store BIOS settings
- (d) To increase CPU speed

> **Why:** Virtual memory keeps only the currently needed pages in RAM and the remainder in **swap space on disk**, so a program larger than physical RAM can run.



**Q. [PYQ] Page fault means:**

- (a) **accessing the page that is not currently in the memory  <-- CORRECT**
- (b) removing the page whenever it is needed
- (c) fetching the page whenever it is needed
- (d) an error that always occurs in the page

> **Why:** A page fault is a **normal, expected event** in demand paging, not a program error. The OS fetches the page from disk, updates the page table and restarts the instruction.



**Q. [EXPECTED] Thrashing occurs when:**

- (a) The CPU is idle
- (b) **The system spends more time swapping pages than executing processes  <-- CORRECT**
- (c) The page table is full
- (d) A deadlock occurs

> **Why:** Caused by too high a degree of multiprogramming, so no process holds enough frames for its **working set**. Cure: reduce multiprogramming or apply the working-set model.



**Q. [EXPECTED] [TRAP] Belady's anomaly is observed in which page replacement algorithm?**

- (a) LRU
- (b) Optimal
- (c) **FIFO  <-- CORRECT**
- (d) LFU

> **Why:** **Belady's anomaly** - more frames producing *more* page faults - occurs in **FIFO** (and Second-Chance). **LRU and Optimal are "stack algorithms"** and never suffer it. A classic one-mark question.



**Q. [EXPECTED] Which page replacement algorithm gives the lowest possible fault rate but cannot be implemented?**

- (a) LRU
- (b) FIFO
- (c) **Optimal (OPT)  <-- CORRECT**
- (d) LFU

> **Why:** Optimal evicts the page not needed for the longest time in the **future**, which requires knowledge no OS has. It is used only as a benchmark against which real algorithms are measured.



**Q. [EXPECTED] [NUMERICAL] With 3 frames and the reference string 1, 2, 3, 4, 1, 2, 5 using FIFO, how many page faults occur?**

- (a) 6
- (b) **7  <-- CORRECT**
- (c) 8
- (d) 9

> **Why:** Every one of the seven references faults: 1,2,3 fill the frames; 4 evicts 1; 1 evicts 2; 2 evicts 3; 5 evicts 4. Total **7 faults**. Work these row by row, writing the frame contents after each reference.



## 3.4 File Systems and Disk Scheduling



> **WEIGHTAGE: 2-3 marks | Disk scheduling trigger phrases are near-certain | Priority HIGH**



### 3.4.1 Questions



**Q. [PYQ] In an acyclic graph directory structure, what is a common method used to implement shared directories or files?**

- (a) File duplication
- (b) **Symbolic (soft) links  <-- CORRECT**
- (c) Hard links
- (d) Directory pointers

> **Why:** Hard links to **directories** are forbidden on UNIX because they could create cycles, destroying the acyclic property. A **symbolic link** stores a path, can point to a directory and can cross file systems - so it is the standard sharing mechanism here.



**Q. [EXPECTED] [TRAP] Which statement about hard and soft links is correct?**

- (a) Both have their own inode
- (b) **A hard link shares the target's inode; a soft link has its own inode containing a path  <-- CORRECT**
- (c) A soft link cannot cross file systems
- (d) Deleting the original breaks a hard link

> **Why:** **Hard link**: same inode, cannot cross file systems, cannot link directories, and the file survives deletion of the original name. **Soft link**: own inode holding a path, crosses file systems, links directories, becomes a dangling link if the target is deleted.



**Q. [EXPECTED] Which file allocation method suffers from external fragmentation?**

- (a) Linked allocation
- (b) Indexed allocation
- (c) **Contiguous allocation  <-- CORRECT**
- (d) FAT

> **Why:** Contiguous allocation gives excellent sequential and direct access but the file cannot grow easily and free space becomes fragmented. **Linked** allocation avoids fragmentation but makes direct access slow; **indexed** allocation supports direct access via an index block.



**Q. [PYQ] The default file system type in Linux is:**

- (a) Ext3
- (b) Ext1
- (c) **Ext4  <-- CORRECT**
- (d) Ext2

> **Why:** **Ext4** adds journaling, extents, delayed allocation and support for very large files and volumes. Ext2 had no journaling.



**Q. [PYQ] [TRAP] Which of the following is NOT true about NTFS?**

- (a) It utilises disk space efficiently using smaller clusters.
- (b) NTFS attributes include read-only, hidden, system, archive, not content indexed, off-line, temporary and compressed.
- (c) It introduced improved performance and scalability compared with its precursor.
- (d) **It does not support the compression of files and directories to optimise storage space.  <-- CORRECT**

> **Why:** NTFS **does** support built-in file and folder compression, along with journaling, ACL-based file-level security, EFS encryption and disk quotas.



**Q. [EXPECTED] Journaling in a file system primarily provides:**

- (a) Faster read speed
- (b) **Crash consistency by logging intended changes before applying them  <-- CORRECT**
- (c) File compression
- (d) Encryption

> **Why:** The journal is written first, so after a crash it can be replayed and the file system is never left in an inconsistent state.



**Q. [PYQ] In which scheduling algorithm does the disk head move in one direction, satisfying all requests until it reaches the end, and then reverses direction?**

- (a) **SCAN  <-- CORRECT**
- (b) SSTF
- (c) LOOK
- (d) FCFS

> **Why:** "**Until it reaches the end**" is the decisive phrase. Learn the three triggers: **SCAN** goes to the physical end then reverses; **LOOK** reverses at the last *request*; **C-SCAN** jumps back to the start without serving on the return.



**Q. [PYQ] [TRAP] The advantage of SSTF (Shortest Seek Time First) is:**

- (a) high variance of response time as SSTF favours only some requests
- (b) overhead to calculate seek time in advance
- (c) **average response time decreases  <-- CORRECT**
- (d) throughput decreases

> **Why:** Three options are **disadvantages** dressed up as advantages. SSTF actually *increases* throughput, and its real drawbacks are starvation of distant requests and high response-time variance.



**Q. [EXPECTED] Which component of disk access time is usually the largest?**

- (a) Rotational latency
- (b) **Seek time  <-- CORRECT**
- (c) Transfer time
- (d) Controller overhead

> **Why:** Moving the arm mechanically dominates. **Access time = seek time + rotational latency + transfer time**, and rotational latency averages half a revolution.



## 3.5 Linux and UNIX



> **WEIGHTAGE: 2-4 marks in DSSSB | EMRS also tests basic OS and ICT commands | Priority HIGH**



### 3.5.1 Questions



**Q. [PYQ] In which of the following directories are the configuration files found?**

- (a) /dev
- (b) /root
- (c) **/etc/  <-- CORRECT**
- (d) /bin

> **Why:** **/etc** = configuration files and administration commands. **/bin** = essential command binaries. **/dev** = device files. **/root** = the superuser's home directory (not the same as `/`).



**Q. [PYQ] [TRAP] Which of the following statements is NOT true?**

- (a) etc: contains additional commands related to system maintenance and administration.
- (b) **usr: It contains temporary files created by Linux or other users.  <-- CORRECT**
- (c) bin: It contains executable files for the UNIX commands.
- (d) dev: It contains device drivers that control various peripherals.

> **Why:** Temporary files live in **/tmp**, not /usr. **/usr** holds user programs and read-only shareable data (/usr/bin, /usr/lib, /usr/share). **/var** holds variable data such as logs.



**Q. [PYQ] Identify the command that is used to delete files in Linux.**

- (a) **rm  <-- CORRECT**
- (b) Rmdir
- (c) Delete
- (d) Rdir

> **Why:** `rm` removes files; `rm -r` removes directories recursively; `rm -f` forces. `rmdir` deletes only **empty** directories. "Delete" and "Rdir" are not Linux commands at all.



**Q. [PYQ] Grep command is used to:**

- (a) change the case of alphabets
- (b) **search for a specific pattern from a specified file and display those lines containing the pattern  <-- CORRECT**
- (c) cut the columns/fields of a specified file
- (d) redirect the output of one command to another command

> **Why:** **GREP = Globally search for a Regular Expression and Print.** Knowing the full form makes the definition unforgettable. The distractors describe `tr`, `cut` and the pipe respectively.



**Q. [EXPECTED] Which command displays the first 10 lines of a file by default?**

- (a) tail
- (b) cat
- (c) **head  <-- CORRECT**
- (d) less

> **Why:** `head` shows the beginning, `tail` the end. `tail -f` follows a growing log file in real time - the standard way to watch server logs.



**Q. [EXPECTED] Which command is used to change file permissions in Linux?**

- (a) chown
- (b) **chmod  <-- CORRECT**
- (c) chgrp
- (d) umask

> **Why:** `chmod` changes **mode** (permissions); `chown` changes **owner**; `chgrp` changes **group**; `umask` sets the *default* permissions for newly created files.



**Q. [PYQ] [NUMERICAL] Which of the following is a default permission for the text file in Linux?**

- (a) rwx r-- r--
- (b) **rw- r-- r--  <-- CORRECT**
- (c) rwx rwx rwx
- (d) rwx --- ---

> **Why:** Files start from base **666** and the standard umask **022** removes group and other write permission, giving **644 = rw-r--r--**. A plain data file is never executable by default. Directories start from 777 and become **755**.



**Q. [EXPECTED] [NUMERICAL] What does chmod 750 file.sh set?**

- (a) rwx rwx r-x
- (b) **rwx r-x ---  <-- CORRECT**
- (c) rw- r-x ---
- (d) rwx r-- r--

> **Why:** Read as three octal digits: 7 = rwx (owner), 5 = r-x (group), 0 = --- (others). Weights are **r=4, w=2, x=1**.



**Q. [PYQ] Which of the following is NOT a shell in Linux?**

- (a) C shell
- (b) Korn shell
- (c) Bourne shell
- (d) **Alpha cell  <-- CORRECT**

> **Why:** No such shell exists - and note the deliberate misspelling "cell" for "shell". Real shells: **sh** (Bourne), **bash** (Bourne Again, the Linux default), **csh** (C shell), **tcsh**, **ksh** (Korn), **zsh**.



**Q. [EXPECTED] Which symbol appends output to an existing file without overwriting it?**

- (a) >
- (b) **>>  <-- CORRECT**
- (c) <
- (d) pipe

> **Why:** `>` overwrites, `>>` appends, `<` takes input from a file, and the pipe sends one command's output into another's input.



**Q. [EXPECTED] Which command shows the currently running processes?**

- (a) ls
- (b) **ps  <-- CORRECT**
- (c) pwd
- (d) du

> **Why:** `ps` reports processes (`ps -ef` shows all); `top`/`htop` give a live view; `kill -9 PID` force-terminates.



**Q. [PYQ] Which of the following is NOT a benefit of distributed systems?**

- (a) Scalability
- (b) **High communication latency  <-- CORRECT**
- (c) Resource sharing
- (d) Fault tolerance

> **Why:** Latency is the classic **drawback**, because messages must cross a network instead of staying inside one machine. Genuine benefits: resource sharing, scalability, fault tolerance, parallel speed-up, geographic distribution.
